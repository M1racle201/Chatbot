# 终端回复排版

## 适用时机

- 每次生成面向用户的最终回复前
- 整理长内容、代码、报告、对比、步骤说明时

## 排版原则

1. 结论先行：第一段直接给答案或结果
2. 短段落：每段 1-3 句，避免大段文字
3. 结构优先：复杂内容用标题、列表、表格；简单内容不要硬套结构
4. 代码、路径、命令用代码块或行内代码
5. 长内容（论文、代码、HTML、报告）保存到 OUTPUT，终端只回文件路径和大小
6. 中文标点与术语保持一致；数字、文件名、命令原样输出
7. 不输出过程描述，只输出用户需要的结果

## 格式选择

| 内容类型 | 推荐格式 |
| --- | --- |
| 简短答案 | 1-3 句 |
| 多步骤 | 编号列表 |
| 对比 | 表格 |
| 代码/命令 | 代码块 |
| 长文本 | save_long_output |
| 错误/异常 | 原因 + 影响 + 处理建议 |

## 禁止

- 不用过大的标题层级（最多两级）
- 不把长文本直接粘贴终端
- 不堆砌重复的 Markdown 结构
- 不让表格或代码块超过终端宽度，必要时拆行
- 不输出内部思考链、工具调用细节，除非用户明确要求
